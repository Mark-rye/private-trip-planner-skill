# 交付合同

## 1. 行程文档

`itinerary.md` 至少包含：

1. 行程结论：节奏、推荐住宿片区、主要取舍、最先预订的项目。
2. 行前清单：证件、预约、交通票、天气和装备。
3. 每日时间轴：时间窗、地点、停留时长、转场方式与时长、用餐/休息、预约和备选。
4. 住宿建议：推荐片区、适合原因、通勤代价、噪音/坡度/停车等风险。
5. 预算：交通、住宿、门票、餐饮和机动金；金额注明币种、适用人数和查询日期。
6. 风险与避坑：触发条件、影响、发现方式、替代方案。
7. 来源与待核实项。

每一天应能回答：从哪里开始、按什么顺序走、怎样转场、何时休息、晚间在哪里结束、若时间不足删什么。

手机阅读页必须同时呈现以上行程内容。短段落、单列卡片和时间轴优先；预算按分类列出，避免需要左右滑动的宽表格。可选的顶层 `overview`、`preparations`、`accommodation`、`budget`、`risks`、`sources` 为字符串或字符串列表；每日 `alternative` 说明删减/雨天方案，每站 `note` 保存预约、休息和执行提示。这些字段由阅读页展示，不能只写进 Markdown。

## 2. 结构化数据

`trip-data.json` 使用 UTF-8 JSON：

```json
{
  "title": "杭州三日轻松行",
  "subtitle": "亲子 · 公共交通 · 2026-10-10 至 2026-10-12",
  "center": [30.25, 120.16],
  "days": [
    {
      "day": 1,
      "date": "2026-10-10",
      "title": "西湖慢游",
      "color": "#E65D3A",
      "summary": "步行较多，午后安排室内休息",
      "stops": [
        {
          "order": 1,
          "name": "示例地点",
          "lat": 30.25,
          "lng": 120.16,
          "time": "09:00–10:30",
          "category": "景点",
          "note": "已预约时段",
          "source_url": "https://example.com"
        },
        {
          "order": 2,
          "name": "示例休息点",
          "lat": 30.26,
          "lng": 120.18,
          "time": "11:00–12:00",
          "note": "坐标与时长为格式示例，不作为旅行推荐"
        }
      ],
      "legs": [
        {
          "from": 1,
          "to": 2,
          "mode": "transit",
          "duration_min": 25,
          "distance_km": 6.2,
          "geometry_status": "schematic"
        }
      ]
    }
  ]
}
```

规则：

- 坐标必须是十进制度，纬度 `-90..90`、经度 `-180..180`。
- `order` 在同一天内唯一，`legs.from/to` 必须引用当日地点。
- `mode` 使用 `walk | transit | drive | bike | ferry | train | flight | other`。
- `geometry_status` 默认 `schematic`，无需真实道路几何。可选 `verified` 仅用于已取得真实路线及来源的场景，不作为交付前提。
- 不知道距离或时长时省略字段，不填 0，不推算成已确认信息。
- 每个地点和已核实路线保留可访问的 `source_url`；坐标来源不能确认时在 `note` 中标记待核实。

## 3. 地图设计

地图是行程决策工具，不是装饰图。

- 按天分色；地点标记同时显示“天数-顺序”，避免只靠颜色区分。
- 手机默认聚焦第一天，顶部横向滑动日签支持一天/总览切换；每次切换自动缩放到该天范围。
- 点击地图编号定位对应行程卡片，卡片显示时间、停留提示和来源；触摸操作不依赖鼠标悬浮。
- 默认使用无外部依赖的简洁示意地图，按真实地理坐标的方向与距离比例绘制；连线为虚线，在卡片中显示交通方式及时间，不要求真实道路。
- 必须显示北向标记和米/公里比例尺，比例尺跟随当前地图范围变化。城市/区域视图使用局部距离投影；长距离总览标注“距离尺度约”，极区或跨洲距离以大圆距离等合适方法处理或拆分地图，不夸大精度。
- 比例尺表示地理直线距离；预计交通时间单独核验。不能为了排版美观随意拖动地点或使用没有地理比例的关系图冒充地图。
- 地图旁保留当天摘要与地点列表，点击列表可定位地图，避免用户只能在图上找点。
- 手机用单列自然滚动，正文至少 16px，操作区域至少 44px。长名称自动换行，详细说明保留在卡片中，图上仅显示编号，避免遮挡。
- 保存后的 HTML 无需加载第三方脚本、字体或地图瓦片即可阅读行程及示意图；来源链接需要联网。
- 页面必须清楚声明：地图用于行程概览；实时导航、路况和班次以当天导航及运营方信息为准。

不要：一次显示所有永久标签、用过多图标遮挡底图、把地图截图当作唯一交付、用直线暗示真实道路、依赖只有桌面鼠标才能触发的交互。

## 4. 交付前检查

- 时间没有重叠，跨城/机场/火车衔接留有缓冲。
- 当天地点在地理上相邻，若不相邻已解释取舍。
- 每天至少有一个删减方案；雨天或闭馆风险有替代。
- 所有时效信息有查询日期或明确标注待核实。
- 地图地点数与文档一致，天数与颜色一致，路线状态没有混淆。
- 页面在 375、390、430px 窄屏下无横向溢出，所有正文、日签、比例尺和卡片可读可触控；用至少一个长地点名称检查换行。
- 关闭网络后，地图和完整行程依然显示；多日切换不丢失当天提示。

数据完整性和预订账目字段见 [guide-blueprint.md](guide-blueprint.md)。可在 legs 中提供
available_min（活动结束到发车的间隔）、transfer_min（到上车点耗时）、buffer_min（候车缓冲），
校验器会拒绝 available_min 小于 transfer_min + buffer_min 的衔接；缺字段时仍须人工检查。
